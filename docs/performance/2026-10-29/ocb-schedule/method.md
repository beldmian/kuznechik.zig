This experiment starts at released v0.9.0, main d42d82cd4ece09b6281aac58cdcbe6edef5d43b7. Only OCB schedule initialization is changed. `snapshots/baseline/ocb.zig` and `snapshots/control/ocb.zig` are byte-for-byte copies of that commit; `snapshots/candidate/ocb.zig` is the measured implementation. The companion empty `ocb_test.zig` files isolate executable-only module imports. Correctness runs use complete source trees and actual tests, not these stubs.

For full-block counts A and P, m=max(A,P). Index i in 1..m can have ntz(i) at most floor(log2(m)); that maximum is attained by the largest power of two no greater than m. The schedule therefore needs bit_length(m) entries, or zero if m=0. AAD and payload partial blocks use L_star. Both L_star and L_dollar remain unconditional, and the 49-entry array still accommodates inclusive block index 2^48 and L48. Validated message lengths imply m<=2^48. Entry i is initialized from the preceding doubled value before use; the full-block loops cannot reference any higher entry. The two-pass opening algorithm and all validation/alias checks are unchanged.

The `bench.zig` executable calls public `Ocb(Cipher).seal` and `open`. It has eight runtime-generated keys, nonces, AAD and plaintext buffers per process, driven by each of seeds 7253, 9189 and 20261029. Each timed invocation includes pool dispatch, input reset memcpy, the complete API including schedule setup, and a compiler observability barrier. Sealing additionally increments a nonce sequence and stores the complete tag. Opening uses already prepared valid ciphertext/tag and retains both private verification and plaintext-writing passes. Allocation, key expansion, reference encryption, whole-buffer comparisons, checksum hashing and logging are outside the timer. No production API allocates. All benchmark buffers are allocated and populated before measurements.

Every case/operation warms both implementations, calibrates an identical iteration count to about 4 ms using the first module, then takes seven alternating paired samples. Iterations are multiples of eight (8..32768), so every pool slot is exercised. Each side of a pair starts with identical nonce/source state. After each sample all eight complete final payloads and, for seals, complete tags are compared; output checksums are accumulated. Intermediate operations are made observable but are not individually compared or hashed inside the timed loop. Reusing/resetting test nonces across differential variants and benchmark cases is only a measurement technique, not nonce-management guidance.

The 89 workload pairs cover the full 0/1/15/16/17-byte AAD/payload cross-product; 64/256/1024/1500/4096/16384-byte records with 0/16/17-byte AAD; independent AAD and payload counts around powers of two and the 64-block batch boundary (through 4097 full blocks, with partial tails); and 1 MiB payload, AAD, or both. The benchmark uses 16-byte tags; the existing independent fixtures exercise every tag length, and the added boundary oracle exercises 1/8/12/16-byte tags.

Compilation is ReleaseFast with Zig 0.15.1, once with `-mcpu=native` and once with explicit portable `-mcpu=x86_64`. The native and portable cipher implementations are otherwise the same released Cipher. Forward layout binds the first module to baseline, second to candidate; reverse swaps them; control binds two distinct byte-identical baseline modules. The same benchmark source and toolchain compile each pair. Symbols/disassembly record actual address placement. Tests and builds finish before timed runs, each pinned to VM core 0, without concurrent compilation or test workloads. Brief SSH status reads and transfers of completed logs occurred during the run; no other CPU-intensive VM jobs were started. Results are wall-time samples from a shared-host VM, not isolated physical hardware or cycle-accurate measurements.

`analyze.py` computes 100*(1-candidate_ns/baseline_ns) for each matched pair. Positive means less time. It aggregates paired ratios and reports controls and seed/layout strata; it never compares independent minima or sums gains from separate experiments. Short-call overhead such as the common reset copy remains included. The throughput result is therefore not a pure kernel measurement or a key-setup/allocation benchmark. Large cases have a minimum of eight operations, potentially substantially longer than the 4 ms calibration target.

The independent boundary generator uses Node/OpenSSL AES-128-OCB, with deterministic varying keys, all nonce lengths 1..15, 280 length/tag combinations, complete ciphertext SHA256 and full expected tags. Tests also check valid opens, whole-buffer preservation on a bad tag, unaligned payload and exterior guards. These supplement the existing 17 Appendix A tuples, nine aggregate checksums, 394 OpenSSL fixtures and 2208 guarded Kuznechik cases. They do not establish registered Kuznechik OCB interoperability. Pure helper tests exercise both axes at every power 2^0..2^48, their predecessors and successors; the huge endpoint is mathematical testing without allocating petabytes.
