Parameter and safety contract:
- Generic RFC section4 nonce: 0..15 bytes. Section3.1 named AES profiles require
  1..15; those names are not Kuznechik profiles. Empty nonce is mathematically
  legal for generic OCB, but may only be used once for encryption under a key.
- Positive byte tags 1..16, fixed by the factory; default16. Any other tag-slice
  length rejects before writes. One tag policy per key is the caller's duty.
- Nonce offset includes TAGLEN, Ktop, Stretch, and every bottom value 0..63.
  L_0..L_48 and ntz indexing include the inclusive 2^48-block endpoint.
- Conservative per-call policy: ceil(AAD bytes/16)+ceil(payload bytes/16)
  <=2^48. This implements the section5 recommended data-block budget for one
  call; lifetime accounting across messages/keys remains external. validate
  supports exact boundary tests without allocating petabyte-sized slices.
- Byte payloads support arbitrary alignment, complete and partial final blocks,
  empty sides, and authentication-only operation. No bit-string API is claimed.
- All writable payload ranges reject overlap with AAD, nonce, detached tag,
  or Cipher storage. Seal output tag additionally rejects overlap with AAD,
  nonce and Cipher. Read-only inputs may overlap each other on open. Empty
  and adjacent slices are allowed. Checks precede all output writes.
- No allocator and no message-sized storage. Payload uses two64-vector scratch
  arrays (blocks and offsets); AAD uses one64-vector scratch array; schedule is
  fixed49 vectors plus L_* and L_$. These are bounded independent of message size.
- Full decryption into private scratch authenticates before a second pass
  releases plaintext. Invalid tags preserve the complete input ciphertext.
  Comparison uses std.crypto.timing_safe.eql; double is branchless. This does
  not make the underlying Kuznechik lookup-based implementation constant-time.
- Caller must prevent concurrent mutation of inputs during calls, including
  the interval between authentication and the second decryption pass.

Correctness evidence:
- All16 RFC7253 Appendix A AES128/tag128 tuples and the separate AES128/tag96
  tuple, both seal and open.
- All9 aggregate checksums: AES128/AES192/AES256 x tag128/tag96/tag64. Each
  aggregate implements all384 inner cases, verifies their decryption, and
  authenticates the final concatenation. AES192 test adapter also checks
  FIPS197 C.2 encryption and inverse. These are AES construction evidence,
  not published Kuznechik OCB vectors.
- 394 independent Node20.19.2/OpenSSL fixtures: AES128 every nonce1..15 and
  tag1..16 (240), AES192/256 each nonce1..15 and tag8/12/16 (90), and all64
  nonce bottom values (64). Data/AAD sizes range0..2049 and include64/128-block
  boundaries. Regeneration compared byte-for-byte with the checked-in JSON.
- OpenSSL rejects empty nonce. Four empty-AAD/payload/nonce AES128 outputs for
  tag1/8/12/16 are separately labelled evaluations of the RFC formulas using
  Node AES-ECB; they are neither published vectors nor OCB-oracle fixtures.
- Kuznechik:138 lengths x16 alignments =2208 guarded cases; lengths0..64,
  1007..1041, 2031..2065, 4095..4097; rotating nonce0..15 and AAD sizes
  0,1,15,16,17,31,32,33,1023,1024,1025. Compare batch output against a scalar
  Cipher adapter; corrupt tags, nonempty nonces, AAD and ciphertext; verify
  rejection preserves whole guarded buffers, then valid open restores input.
- Dimensions, exact length-budget boundaries, malformed tag slices, empty and
  adjacent slices, both pointer-order overlap directions, output-tag aliases,
  Cipher storage aliases, read-only sharing, and no-write failures covered.
- Instrumented Cipher verifies at-most64 independent blocks per batch and
  two private batches on a failed1041-byte open versus four decrypt batches
